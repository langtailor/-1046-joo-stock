**4장 1) 단계별 개발 일정 재작성**

- 2주 단위 **스프린트 5회** 구조로 전환. 스프린트 경계는 기존 주차 구분(착수일 기준 7일 단위)과 맞물리도록 잡아 날짜 불일치가 생기지 않게 함
- 스프린트 5는 13일. 전체 69일과 합계 일치 확인 (14 × 4 + 13 = 69)
- 담당자별 레인 5개(팀원 4명 + 공통), 컬럼 5개(백로그 / 할 일 / 진행 중 / 리뷰 / 완료)로 칸반 보드 작성
- 카드 상태를 완료 / 진행 가능 / 선행 확인 대기 / 미배정 4종으로 구분하고 범례 추가
- 스크럼 운영 규칙 표 추가 — 스프린트 계획, 데일리 스크럼, 스프린트 리뷰, 회고

**DNS 사전 생성 조사**

- `ragtailor.com` · `ragtaylor.com` 모두 **Cloudflare** 네임서버(`aaron`/`ines.ns.cloudflare.com`) 사용 확인
- `fin.ragtailor.com` **NXDOMAIN** — 미생성 상태이며 덮어쓸 레코드 없음
- `_github-pages-challenge-ragtailor.ragtailor.com` **NXDOMAIN** — GitHub 도메인 소유 확인 미설정
- 이 PC에 `dig`·`host`가 없어 DNS-over-HTTPS로 조회. Cloudflare 자격증명·CLI도 없어 레코드 생성은 대시보드에서 직접 해야 함
- 소유 확인 TXT 없이 CNAME만 선행 생성하면 서브도메인 탈취가 가능한 상태가 되므로, **TXT 소유 확인 → CNAME** 순서로 `/todo/`에 절차 기록

**RFP 하네스 작성**

- `.claude/rules/rfp-harness.md` 작성 — 요구사항 11개 분류 체계(`SFR`/`PER`/`SER`/`QUR`/`SIR`/`DAR`/`TER`/`ECR`/`CSR`/`PMR`/`PSR`), 작성 품질 기준(명확성·원자성·추적성·검증성), 추적성 매트릭스, 사업관리(PMR), 스캐폴딩 태스크, 자체 검증 루틴
- 외부 참고 자료의 `SEC`·`QUA` 표기를 표준 표기 `SER`·`QUR`로 정정
- 참고 자료의 발주기관 「(가칭) 조달청 산하 국가금융데이터지능화센터」는 **기입하지 않고 금지 항목으로 등록.** 가칭을 실재 기관처럼 쓰는 표기이며 발주처는 여전히 미확정
- 참고 자료가 인용한 `PER-002`는 명세표에 없는 ID여서 `SFR-002`/`PER-001`로 정정

**스택·조직 결정**

- **클라이언트 스택을 Flutter로 확정.** 참고 자료의 Next.js/Vercel 웹 구성은 미채택
- **R&R은 4장 2) 배정을 유지.** 참고 자료가 테일러를 FE 개발, 왓슨을 BE, 토마스를 Infra로 배정했으나 채택하지 않음. 테일러는 PM 전담이며, 4명 편성에서 PM에게 개발 모듈을 겸하게 하면 진척 관리에 공백이 생긴다는 판단
- **벡터 저장소를 Aurora PostgreSQL + pgvector로 확정.** 참고 자료의 OpenSearch/Pinecone은 미채택이며 별도 벡터 DB를 두지 않음. 같은 날 생성한 Aurora Serverless v2 클러스터와 `.env.example`의 `RDS_*` 키를 그대로 사용
- **Flutter 빌드 대상을 Android · iOS로 확정.** 웹 타깃은 제외. 스캐폴딩은 `flutter create --platforms=android,ios`로 생성
- **기능 우선순위를 필수/선택 2단계로 확정.** 2장 5)에 등급 정의를 기재. 3단계 이상이나 MoSCoW 등 다른 체계는 도입하지 않음. 스프린트 배정 시 필수 항목을 앞 스프린트에 먼저 배치
- 다섯 결정으로 `/todo/` 확인필요의 「클라이언트 스택 확정」·「R&R 재정의 여부」·「벡터 저장소 확정」·「Flutter 빌드 대상 플랫폼」·「기능 우선순위 기준」 해소. **착수 시점의 확인필요 2건이 모두 해소되었고, 스택 관련 미결도 남아 있지 않음**. RFP 하네스의 스택 충돌 절은 전부 해소되어 확정 절로 전환

**2장 개발 요구 사항 본문 작성**

- 확정된 기술 결정(Flutter Android/iOS, Aurora pgvector, 하이브리드 검색)과 표지 제목의 성과 목표에서 도출해 작성. 요구 ID `SFR-001`~`004`, `PER-001`, `SER-001` 부여
- 1) 목적, 2) 개발 범위, 5) 대민 서비스 기능, 6) 시스템 아키텍처 작성 완료
- 2) 제외 범위에 **웹 채널**과 **별도 벡터 DB 도입**을 명시. 확정 결정에서 직접 도출한 값
- 3)은 원천(DART 전자공시 / SEC EDGAR)만 기재하고 대상 범위·연계 방식·수집 주기는 업무 요건이므로 비워 둠
- 4) 미디어 자동화 처리는 **절 전체를 비워 둠.** 정본인 표지 제목에 대응되는 내용이 없어 확인 항목으로 등록
- 7)의 근거 열은 전부 *확인 필요*. 확인되지 않은 법령·조항을 인용하지 않음
- 처음에 품질 요구 사항(`QUR`) 절을 따로 만들었으나 목차의 7개 항목과 어긋나 제거하고, 3장 3)으로 넘기는 포인터만 남김

**1장 2) 주요 사업 내용 작성**

사업 범위
- 포함 4건을 세부 과제와 1:1로 맞추고, 제외에 웹 채널과 별도 벡터 DB 도입을 명시. 2장 2)와 같은 값이므로 한쪽만 고치지 말라는 주석을 남김
- 수행 기간 69일 / 약 10주를 명시

대상 시스템 및 데이터
- 데이터 원천은 DART 전자공시(XML·HTML)와 SEC EDGAR(10-K 등). 대상 기업·기간·보고서 종류는 미확정
- 신규 구축 시스템 4종을 세부 과제와 연결
- **「기존 시스템」을 확인 필요로 등록.** `PER-001`의 "기존 대비 40% 절감"은 비교 대상 시스템이 있어야 판정할 수 있으며, 이는 기준선 미정의 항목과 같은 사안임
- **「연계 기관」은 비워 둠.** 데이터 원천을 운영하는 기관과 연계 기관은 다르며, 공개 데이터 이용으로 충분한지 별도 협약이 필요한지가 확정되지 않음. 원천 운영 기관을 연계 기관 칸에 옮겨 적지 말라는 주석을 남김

세부 과제

- 2장 요구 사항에서 역산해 과제 4건 정의. 각 과제에 2장 대응 절과 요구 ID를 부여해 1:1 대응을 명시
- 과제 1 공시 문서 수집 및 구조화(2장 3), 과제 2 하이브리드 검색·응답 엔진(6), 과제 3 대민 서비스 앱(5), 과제 4 플랫폼 기반 및 보안(6·7)
- 2장 1) 목적과 2) 개발 범위는 과제가 아니라 적용 기준을 정의하는 절이므로 대응 대상에서 제외하고, 그 근거를 양쪽 장에 기재
- **5번 과제는 비워 둠.** 2장 4) 미디어 자동화 처리가 미확정이라 대응 과제를 정의할 수 없음. 1장↔2장 1:1 대응이 이 항목 하나로 막혀 있음
- 2장 머리의 "1장 세부 과제 미작성" 경고를 대응 관계 설명으로 교체

## 확인 필요

- **실제 발주처** — 미표기 상태 유지 중
- **2장 4) 미디어 자동화 처리** — 정본인 표지 제목(공시 문서 구조화 및 Hybrid RAG pipeline)에 대응되는 내용이 없습니다. 「미디어 자동화」는 표지 영문 부제에서 온 항목이며, 무엇을 자동 생성한다는 것인지 확정되지 않아 절 전체를 비워 두었습니다
- **2장 3) 데이터 원천 세부** — 대상 기업·기간·보고서 종류, 연계 방식, 수집 주기. 저장 용량과 파싱 처리량이 이 값에 달려 있습니다
- **2장 7) 법령 근거** — 개인정보 수집 여부 자체를 먼저 확정해야 합니다
- **2장 5) 선택 등급 기능** — 필수 4건은 확정 기술 결정에서 도출했으나 선택 등급이 비어 있습니다. 등급 배정 자체도 PM 검토가 필요합니다
- **연계 기관** — 공개 데이터 이용으로 충분한지, 별도 협약이 필요한지 확정되지 않았습니다. 협약이 필요하다면 10주 일정 안에 절차가 들어가야 합니다
- **`PER-001` 비교 기준선** — "기존 대비 -40%"의 기준선이 정의되지 않아 판정할 수 없습니다. 표지 제목의 `Latency -40%`도 같은 근거를 씁니다
- **청크 수 · 임베딩 차원** — pgvector 확정으로 ACU 산정과 인덱스(HNSW/IVFFlat) 파라미터가 이 두 값에 걸리게 되었습니다. HNSW 인덱스가 메모리에 올라가지 않으면 검색 지연이 급격히 나빠집니다
- **대민 서비스 접근 채널** — 클라이언트가 Android / iOS 앱으로 확정되면서 웹 채널이 없습니다. 2장 5)에서 웹 접근 경로나 웹 접근성 요구가 나오면 이 결정을 재확인해야 합니다
