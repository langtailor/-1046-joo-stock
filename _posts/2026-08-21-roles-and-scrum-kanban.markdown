**4장 1) 단계별 개발 일정 재작성**

- 2주 단위 **스프린트 5회** 구조로 전환. 스프린트 경계는 기존 주차 구분(착수일 기준 7일 단위)과 맞물리도록 잡아 날짜 불일치가 생기지 않게 함
- 스프린트 5는 13일. 전체 69일과 합계 일치 확인 (14 × 4 + 13 = 69)
- 담당자별 레인 5개(팀원 4명 + 공통), 컬럼 5개(백로그 / 할 일 / 진행 중 / 리뷰 / 완료)로 칸반 보드 작성
- 카드 상태를 완료 / 진행 가능 / 선행 확인 대기 / 미배정 4종으로 구분하고 범례 추가
- 스크럼 운영 규칙 표 추가 — 스프린트 계획, 데일리 스크럼, 스프린트 리뷰, 회고

**DNS 사전 생성 조사**

- `ragtailor.com` · `ragtaylor.com` 모두 **Cloudflare** 네임서버(`aaron`/`ines.ns.cloudflare.com`) 사용 확인
- `fin.ragtailor.com` **NXDOMAIN** — 미생성 상태이며 덮어쓸 레코드 없음
- `_github-pages-challenge-ragtailor.ragtailor.com` **NXDOMAIN** — GitHub 도메인 소유 확인 미설정
- 이 PC에 `dig`·`host`가 없어 DNS-over-HTTPS로 조회. Cloudflare 자격증명·CLI도 없어 레코드 생성은 대시보드에서 직접 해야 함
- 소유 확인 TXT 없이 CNAME만 선행 생성하면 서브도메인 탈취가 가능한 상태가 되므로, **TXT 소유 확인 → CNAME** 순서로 `/todo/`에 절차 기록

**RFP 하네스 작성**

- `.claude/rules/rfp-harness.md` 작성 — 요구사항 11개 분류 체계(`SFR`/`PER`/`SER`/`QUR`/`SIR`/`DAR`/`TER`/`ECR`/`CSR`/`PMR`/`PSR`), 작성 품질 기준(명확성·원자성·추적성·검증성), 추적성 매트릭스, 사업관리(PMR), 스캐폴딩 태스크, 자체 검증 루틴
- 외부 참고 자료의 `SEC`·`QUA` 표기를 표준 표기 `SER`·`QUR`로 정정
- 참고 자료의 발주기관 「(가칭) 조달청 산하 국가금융데이터지능화센터」는 **기입하지 않고 금지 항목으로 등록.** 가칭을 실재 기관처럼 쓰는 표기이며 발주처는 여전히 미확정
- 참고 자료가 인용한 `PER-002`는 명세표에 없는 ID여서 `SFR-002`/`PER-001`로 정정

**스택·조직 결정**

- **클라이언트 스택을 Flutter로 확정.** 참고 자료의 Next.js/Vercel 웹 구성은 미채택
- **R&R은 4장 2) 배정을 유지.** 참고 자료가 테일러를 FE 개발, 왓슨을 BE, 토마스를 Infra로 배정했으나 채택하지 않음. 테일러는 PM 전담이며, 4명 편성에서 PM에게 개발 모듈을 겸하게 하면 진척 관리에 공백이 생긴다는 판단
- **벡터 저장소를 Aurora PostgreSQL + pgvector로 확정.** 참고 자료의 OpenSearch/Pinecone은 미채택이며 별도 벡터 DB를 두지 않음. 같은 날 생성한 Aurora Serverless v2 클러스터와 `.env.example`의 `RDS_*` 키를 그대로 사용
- **Flutter 빌드 대상을 Android · iOS로 확정.** 웹 타깃은 제외. 스캐폴딩은 `flutter create --platforms=android,ios`로 생성
- 네 결정으로 `/todo/` 확인필요의 「클라이언트 스택 확정」·「R&R 재정의 여부」·「벡터 저장소 확정」·「Flutter 빌드 대상 플랫폼」 해소. RFP 하네스의 스택 관련 미결은 남아 있지 않음. RFP 하네스의 스택 충돌 절은 전부 해소되어 확정 절로 전환

## 확인 필요

- **실제 발주처** — 미표기 상태 유지 중
- **기능 우선순위(필수/선택) 기준** — 스프린트 목표 배정의 전제. 왓슨·앨리스·토마스 세 레인의 개발 카드가 이 항목 때문에 백로그에 묶여 있습니다. 10주 일정에서 대기가 길어질수록 후반 스프린트가 압축됩니다
- **`PER-001` 비교 기준선** — "기존 대비 -40%"의 기준선이 정의되지 않아 판정할 수 없습니다. 표지 제목의 `Latency -40%`도 같은 근거를 씁니다
- **청크 수 · 임베딩 차원** — pgvector 확정으로 ACU 산정과 인덱스(HNSW/IVFFlat) 파라미터가 이 두 값에 걸리게 되었습니다. HNSW 인덱스가 메모리에 올라가지 않으면 검색 지연이 급격히 나빠집니다
- **대민 서비스 접근 채널** — 클라이언트가 Android / iOS 앱으로 확정되면서 웹 채널이 없습니다. 2장 5)에서 웹 접근 경로나 웹 접근성 요구가 나오면 이 결정을 재확인해야 합니다
