# 공공 SW사업 RFP 하네스

제안요청서(RFP) 요구사항을 **명확성·원자성·추적성·검증성** 기준으로 다루기 위한
규칙이다. 제안서 본문(`*.markdown`)과 앞으로 생성할 코드베이스 양쪽에 적용한다.

이 문서는 **요구사항을 어떻게 쓰고 추적할지**를 정한다. 요구사항의 *내용* 자체는
2장 개발 요구 사항(`requirements.markdown`)이 정본이며, 확정 전까지 여기서
지어내지 않는다.

---

## 0. 절대 금지 (다른 모든 규칙에 우선한다)

국가사업 문서다. 추정으로 채운 문장이 그대로 제출될 위험이 있다.

- **발주처·기관명을 임의로 표기하지 않는다.** 특히 `조달청 산하 국가금융데이터지능화센터`
  같은 **가칭 기관명을 실재하는 것처럼 쓰지 않는다.** 외부 참고 자료에 그런 이름이
  적혀 있어도 옮기지 않는다. 실제 발주처는 `/todo/` 확인필요 항목이며 사용자 확인
  후에만 기입한다.
- **근거 없는 표준·지침명을 인용하지 않는다.** 목차 양식의 출처는 한국소프트웨어진흥원
  제안요청서 양식안이며, **해당 기관은 양식의 출처일 뿐 발주처가 아니다.**
- **미확정 기술 스택을 확정된 것처럼 쓰지 않는다.** §5의 충돌 항목을 먼저 확인한다.
- **정량 지표를 지어내지 않는다.** 수치를 쓰려면 산출 근거나 측정 방법을 함께 쓴다.
- 날짜·기간·인원은 `date` 등으로 **계산해 검증한 뒤** 기입한다.

## 1. 요구사항 분류 체계

공공 SW사업 제안요청서에서 통용되는 11개 분류를 쓴다. ID는 `<분류코드>-<3자리 일련번호>`
형식이다 (예: `SFR-001`).

| 코드 | 분류 | 이 사업에서의 상태 |
| :--- | :--- | :--- |
| `SFR` | 기능 요구사항 | 잠정 4건 (§4) |
| `PER` | 성능 요구사항 | 잠정 1건 (§4) |
| `SER` | 보안 요구사항 | 잠정 1건 (§4) |
| `QUR` | 품질 요구사항 | 잠정 1건 (§4) |
| `SIR` | 인터페이스 요구사항 | 미작성 |
| `DAR` | 데이터 요구사항 | 미작성 |
| `TER` | 테스트 요구사항 | 미작성 |
| `ECR` | 시스템 장비구성 요구사항 | 미작성 |
| `CSR` | 제약사항 | 미작성 |
| `PMR` | 프로젝트 관리 요구사항 | §6 |
| `PSR` | 프로젝트 지원 요구사항 | 미작성 |

- 코드 표기는 발주처 양식에 따라 다를 수 있다. **발주처 확정 후 그 양식에 맞춘다.**
- 외부 자료에서 흔히 쓰는 `SEC-xxx`·`QUA-xxx`는 이 체계의 `SER`·`QUR`로 옮겨 적는다.
- 번호는 재사용하지 않는다. 폐기된 요구사항은 번호를 비워 두고 이력만 남긴다.

## 2. 작성 품질 기준

### 2.1 명확성 — 검증 가능한 문장으로 쓴다

정성적 표현을 그대로 두지 않는다. 측정 주체·조건·수치를 명시한다.

| 쓰지 않는다 | 이렇게 쓴다 |
| :--- | :--- |
| 빠르게 처리한다 | 정상 부하에서 E2E 응답 시간을 기존 대비 40% 절감하고, 첫 토큰 출력까지 1.5초 이내 |
| 안정적으로 동작한다 | (측정 조건과 임계값을 정의한 뒤 다시 쓴다) |
| 사용자 편의를 높인다 | (관찰 가능한 동작으로 다시 쓴다) |

조건을 정할 근거가 없으면 **비워 두고 `*작성 예정*`으로 표시한다.** 임의로 수치를
채우지 않는다.

### 2.2 원자성 — 하나의 ID는 하나의 검증 단위

- 한 요구사항 ID가 독립적으로 검수 가능해야 한다.
- "그리고"·"또한"으로 두 기능이 묶여 있으면 ID를 나눈다.
- 나눌 수 없다면 검수 기준을 여러 개 두고 각각 판정 가능하게 만든다.

### 2.3 추적성 — 요구 ID가 코드까지 이어진다

생성하는 **모든** 소스·테스트·설정 파일 상단에 관련 요구 ID를 주석으로 남긴다.

```python
# Requirement ID: SFR-002
# 검수 기준: Top-5 문서 추출 시 Recall@5 92% 이상
```

```typescript
// Requirement ID: SFR-003
// 검수 기준: 답변 각주 클릭 시 원문 해당 위치로 auto-scroll
```

- 여러 요구사항에 걸치면 모두 나열한다.
- 요구 ID가 없는 파일은 스캐폴딩·설정 파일에 한한다. 기능 코드에는 반드시 붙인다.
- 커밋 메시지 제목에도 관련 ID를 넣는다 (예: `SFR-002 하이브리드 검색기 구현`).

### 2.4 검증성 — 검수 기준과 테스트를 함께 만든다

요구사항 구현 코드를 생성할 때 **그 요구사항의 검수 기준을 판정하는 테스트를 같은
작업에서 함께 생성한다.** 테스트 없이 구현만 만들지 않는다.

- 테스트 파일에도 요구 ID 주석을 붙인다.
- 검수 기준이 수치면 테스트가 그 수치를 실제로 판정해야 한다. `assert True`로
  자리만 채우지 않는다.
- **검증하지 않은 완료 처리를 하지 않는다.** 서버가 떴다면 실제 응답 코드를 확인한
  뒤 기록한다.

## 3. 추적성 매트릭스

요구사항 하나는 아래 네 칸이 모두 채워져야 "완료"로 볼 수 있다.

```
요구 ID  →  구현 코드 경로  →  테스트 경로  →  검수 기준 판정 결과
```

| 칸 | 채우는 시점 | 비어 있으면 |
| :--- | :--- | :--- |
| 요구 ID | 2장 요구사항 확정 시 | 착수 불가 |
| 구현 코드 경로 | 구현 착수 시 | 미착수 |
| 테스트 경로 | 구현과 동시 | **완료 처리 금지** |
| 판정 결과 | 테스트 실행 후 | **완료 처리 금지** |

## 4. 요구사항 명세표 (잠정)

> **상태: 잠정.** 아래 항목은 외부 참고 자료에서 가져온 초안이며 **2장 개발 요구
> 사항으로 확정되지 않았다.** 확정 전까지 이 표를 근거로 코드 구조를 고정하지 않는다.
> 확정되면 `requirements.markdown`을 정본으로 삼고 이 표를 그에 맞춘다.

### 4.1 기능 (SFR)

| 요구 ID | 정의 | 코드 위치(안) | 검수 기준 |
| :--- | :--- | :--- | :--- |
| `SFR-001` | DART(XML/HTML) 및 SEC(10-K) 내 복합 표·텍스트 구조화 파싱 | `services/parser/` | 표 구조 복원율 95% 이상 (테스트셋 기준) |
| `SFR-002` | Dense(임베딩) + Sparse(BM25) 앙상블 및 재순위화 | `services/rag/retriever.py` | Top-5 추출 시 Recall@5 92% 이상 |
| `SFR-003` | 답변 근거 원문 위치 하이라이팅 및 좌표 제공 | `apps/app/` (Flutter · Android/iOS) | 각주 탭 시 원문 해당 위치로 auto-scroll |
| `SFR-004` | 대화 맥락을 유지하는 멀티턴 질의응답 API | `services/api/routers/chat.py` | 이전 대화 컨텍스트 반영 질의 성공 |

`SFR-001`의 95%, `SFR-004`의 성공률은 **측정 데이터셋과 판정 방법이 정의되지 않았다.**
정의 전까지 검수 기준으로 쓰지 않는다.

### 4.2 성능·보안·품질

| 요구 ID | 정의 | 코드 위치(안) | 검수 기준 |
| :--- | :--- | :--- | :--- |
| `PER-001` | E2E 응답 시간 기존 대비 40% 절감, 첫 토큰 1.5초 이내 | `services/rag/pipeline.py` | 부하 테스트 평균 응답 -40% 달성 |
| `SER-001` | 프런트엔드-백엔드 간 인증 및 CORS 통신 보안 | `services/api/middleware/` | 미인가 요청 401/403 차단, CORS 검증 통과 |
| `QUR-001` | 요구 ID별 자동화 단위 테스트 | `tests/` | 핵심 RAG·API 로직 커버리지 80% 이상 |

`PER-001`의 "기존 대비"는 **비교 기준선(baseline)이 정의되어야 판정할 수 있다.**
무엇 대비 40%인지 먼저 확정한다. 표지 제목의 `Latency -40%`도 같은 근거를 쓴다.

측정 시 주의 — Aurora Serverless v2 최소 용량이 0 ACU면 5분 비활성 후 일시 중지되고
재개에 십수 초가 걸린다. **성능 측정 구간에서는 최소 용량을 올려 콜드 스타트가
측정값에 섞이지 않게 한다.**

## 5. 조직 구성과 충돌 항목

### 5.1 확정된 역할 (정본: `schedule.markdown` 4장 2))

| 이름 | 역할 | 담당 모듈(안) |
| :--- | :--- | :--- |
| 테일러 | PM | 일정·범위 관리, 백로그 우선순위, 산출물 검토 |
| 왓슨 | 앱 개발 (Flutter) | `apps/app` |
| 앨리스 | 파이프라인 개발 | `services/parser`, `services/rag` |
| 토마스 | 에이전트 개발 | `services/api`, 에이전트 오케스트레이션 |

**2026-08-21 확정 — 이 배정을 유지한다.** 외부 참고 자료가 테일러를 FE 개발,
왓슨을 BE, 토마스를 Infra로 배정하고 있으나 **채택하지 않기로 결정했다.**
참고 자료의 R&R 표를 근거로 위 배정을 다시 바꾸지 않는다.

테일러는 PM 전담이다. 4명 편성에서 PM에게 개발 모듈을 겸하게 하면 진척 관리에
공백이 생긴다. 변경하려면 4장 2)를 먼저 고치고 근거를 개발 로그에 남긴다.

### 5.2 클라이언트 스택 — Flutter 확정

**2026-08-21 확정.** 대민 서비스 클라이언트는 **Flutter**로 구현한다. 담당은 왓슨이다.

- 참고 자료의 **Next.js / Vercel 웹 구성은 채택하지 않는다.** 참고 자료에 Flutter가
  없다는 이유로 웹 스택을 되살리지 않는다.
- `apps/web`·Vercel 배포·Next.js App Router 전제의 지시는 이 프로젝트에 적용하지 않는다.

**빌드 대상은 Android / iOS 두 가지로 확정한다 (2026-08-21).**

- 스캐폴딩은 `flutter create --platforms=android,ios` 로 생성한다.
  `web`·`windows`·`macos`·`linux` 타깃을 임의로 추가하지 않는다.
- **웹 채널이 없다.** `SFR-003`의 원문 뷰어는 브라우저 렌더링에 기대지 말고
  모바일에서 동작하는 방식으로 설계한다. PDF/HTML 표시 방식은 2장 요구사항
  확정 후 정한다.
- 대민 서비스인데 웹 채널이 빠져 있다. 2장 5) 대민 서비스 플랫폼 기능에서
  접근 채널이나 웹 접근성 요구가 나오면 **이 결정을 다시 확인해야 한다.**
  그때까지는 Android / iOS 전제로 진행한다.

### 5.3 벡터 저장소 — Aurora PostgreSQL + pgvector 확정

**2026-08-21 확정.** 벡터 저장소는 **Aurora Serverless v2 (PostgreSQL) + pgvector**를
쓴다. 클러스터는 같은 날 생성되었고 `.env.example`도 이 전제로 작성되어 있다.

- 참고 자료의 **OpenSearch / Pinecone은 채택하지 않는다.** 별도 벡터 DB를 추가로
  두지 않는다. 관계형 데이터와 벡터를 한 엔진에서 다루므로 `SFR-002`의 Sparse(BM25)
  검색도 PostgreSQL 안에서 구성하는 방향을 먼저 검토한다.
- 접속 키는 `.env.example`의 `RDS_*` 계열을 쓴다. 새 키가 필요하면 `.env.example`에
  먼저 추가하고 값은 `.env`에 둔다.

운영상 주의 — pgvector의 HNSW 인덱스가 메모리에 올라가지 않으면 검색 지연이 급격히
나빠진다. 필요한 ACU는 **청크 수와 임베딩 차원**으로 결정되는데 둘 다 아직 미확정이다.
확정되면 그때 산정하고 근거를 남긴다. 지금 단계에서는 최소 0 / 최대 4 ACU로 충분하다.

## 7. 스캐폴딩 태스크

> **선행 조건.** 아래 태스크는 2장 요구사항이 확정된 뒤에 착수한다. 그 전에
> 실행하면 잘못된 전제로 코드베이스가 고정된다. 스택 자체는 확정되었다 —
> 클라이언트 Flutter(§5.2), 벡터 저장소 Aurora pgvector(§5.3).

### Task 1 — 모노레포 뼈대

- 워크스페이스 구성: `apps/app`(Flutter), `services/api`, `services/rag`,
  `services/parser`, `infra/`
- 클라이언트는 **Flutter**로 생성한다 (§5.2).
  `flutter create --platforms=android,ios apps/app`
- API 서버에 CORS 미들웨어 설정 (`SER-001`)
- 생성하는 모든 파일 상단에 요구 ID 주석 (§2.3)

### Task 2 — `SFR-002` 하이브리드 검색기

- `services/rag/retriever.py` — Dense + Sparse 결합, RRF 재순위화
- 저장소는 **Aurora pgvector**다 (§5.3). 접속은 `.env`의 `RDS_*` 키를 쓴다.
- `tests/test_retriever.py` — **`SFR-002`의 Recall@5 92% 기준을 실제로 판정**하는 테스트
- 평가 데이터셋이 없으면 **테스트를 먼저 만들 수 없다.** 데이터셋 확보를 선행 과제로 올린다.
