> 본 장의 항목은 [1장 사업 개요]({{ '/about/' | relative_url }})의 「세부 과제」와 **1:1로 대응**되도록 작성합니다. 두 장이 어긋나면 심사에서 지적되기 쉽습니다.
>
> **현재 1장 「세부 과제」가 미작성 상태입니다.** 아래 요구 사항은 확정된 기술 결정과 표지 제목의 성과 목표에서 도출한 것이며, 1장이 작성되면 대응 관계를 다시 맞춰야 합니다.

요구 사항에는 추적을 위해 분류 코드와 ID를 부여합니다. `SFR` 기능, `PER` 성능, `SER` 보안입니다. 품질·테스트 요구 사항(`QUR`)은 [3장 3) 품질 관리 및 테스트]({{ '/guidelines/' | relative_url }}#s3-3)에서 다룹니다.

## 1) 목적 {#s2-1}

본 장은 「금융 공시(DART/SEC) 복합 문서 구조화 및 Hybrid RAG pipeline 구축」에 필요한 개발 요구 사항을 정의합니다.

- **적용 대상**: 본 사업으로 개발하는 파싱 파이프라인, 검색·응답 엔진, 대민 서비스 앱, 이를 지원하는 인프라 전체
- **적용 기준**: 각 요구 사항은 독립적으로 검증 가능해야 하며, 검수 기준을 측정 가능한 형태로 함께 명시합니다
- **미확정 항목의 처리**: 확정되지 않은 항목은 임의로 채우지 않고 *작성 예정*으로 남깁니다

## 2) 개발 범위 {#s2-2}

| 구분 | 범위 | 비고 |
| --- | --- | --- |
| 포함 | DART·SEC 공시 문서 수집 및 복합 표/텍스트 구조화 파싱 | `SFR-001` |
| 포함 | Dense + Sparse 하이브리드 검색 및 재순위화 엔진 | `SFR-002` |
| 포함 | 답변 근거 원문 위치 제시 기능 | `SFR-003` |
| 포함 | 멀티턴 금융 질의응답 API | `SFR-004` |
| 포함 | Android · iOS 대민 서비스 앱 (Flutter) | 2026-08-21 확정 |
| 포함 | Aurora PostgreSQL + pgvector 기반 저장소 구성 | 2026-08-21 확정 |
| 제외 | **웹 채널** | 빌드 대상을 Android · iOS로 한정. 접근 채널 요구가 추가되면 재검토 |
| 제외 | **별도 벡터 DB 도입** | OpenSearch·Pinecone 등을 추가하지 않고 pgvector로 처리 |
| 제외 | *작성 예정* | 데이터 원천 확정 후 수집 대상에서 제외할 범위를 명시 |

> 제외 범위를 명시하지 않으면 사업 종료 시점에 분쟁 소지가 됩니다. 포함만큼 제외를 분명히 적으십시오.

## 3) 금융데이터 수집 및 연계 {#s2-3}

| 항목 | 내용 |
| --- | --- |
| 데이터 원천 | 국내 — DART 전자공시 (XML / HTML)<br>국외 — SEC EDGAR (10-K 등) |
| 대상 문서 범위 | *작성 예정* — 대상 기업·기간·보고서 종류를 확정해야 합니다 |
| 연계 방식 | *작성 예정* — 공개 API 사용 여부 및 인증 방식 확정 필요 |
| 수집 주기 | *작성 예정* — 정기 수집인지 요청 시 수집인지 확정 필요 |
| 데이터 형식 | XML · HTML 원문과 이를 구조화한 중간 표현 |
| 품질 기준 | 표 구조 복원율 **95% 이상** (`SFR-001`) — 단, 측정용 테스트셋이 정의되어야 판정 가능 |

**`SFR-001` 복합 문서 구조화 파싱** — DART·SEC 공시 문서 내 복합 표(병합 셀, 다단 헤더)와 본문 텍스트를 검색 가능한 구조로 변환합니다. 표의 행·열 관계가 보존되어야 하며, 원문 위치 정보를 함께 보관해 `SFR-003`에서 참조할 수 있게 합니다.

> 대상 문서 범위와 수집 주기는 **업무 요건이므로 확인 후 기입합니다.** 이 값에 따라 저장 용량과 파싱 처리량이 결정됩니다.

## 5) 대민 서비스 플랫폼 기능 {#s2-5}

우선순위는 **필수 / 선택 2단계**로 구분합니다 (2026-08-21 확정). 3단계 이상으로 나누거나 다른 등급을 추가하지 않습니다.

| 등급 | 의미 |
| --- | --- |
| **필수** | 본 사업 기간 내에 반드시 구현합니다. 미구현 시 해당 요구 사항은 미이행으로 봅니다. |
| **선택** | 필수 항목을 완료한 뒤 잔여 기간에 구현합니다. 미구현이 곧 미이행은 아니며, 사유를 개발 로그에 남깁니다. |

## 6) 시스템 아키텍처 {#s2-6}

| 계층 | 구성 | 비고 |
| --- | --- | --- |
| 클라이언트 | Flutter 앱 (Android · iOS) | 웹 타깃 제외. `apps/app` |
| 서비스 | 질의응답 API, 인증, 라우팅 | `services/api` |
| 처리 | 하이브리드 검색·재순위화 엔진 (`SFR-002`) | `services/rag` |
| 처리 | 공시 문서 파싱 파이프라인 (`SFR-001`) | `services/parser` |
| 데이터 | Aurora Serverless v2 (PostgreSQL) + pgvector | 관계형 데이터와 벡터를 단일 엔진에서 처리 |
| 인프라 | AWS. IAM 계정 기반 접근 통제 | `infra/` |

**`SFR-002` 하이브리드 검색** — Dense(임베딩) 검색과 Sparse(BM25) 검색 결과를 결합하고 재순위화하여 상위 문서를 반환합니다. 검수 기준은 **Recall@5 92% 이상**이며, 평가용 데이터셋이 정의되어야 판정할 수 있습니다.

**`PER-001` 성능 요건** — 파이프라인 전체의 E2E 응답 시간을 기존 대비 **40% 절감**하고, 첫 토큰 출력까지 **1.5초 이내**를 만족해야 합니다.

> `PER-001`의 "기존 대비"는 **비교 기준선이 정의되어야 판정할 수 있습니다.** 무엇 대비 40%인지 확정하십시오. 표지 제목의 `Latency -40%`도 같은 근거를 사용합니다.
>
> 성능 측정 시 Aurora Serverless v2의 최소 용량이 0 ACU이면 일시 중지 후 재개에 십수 초가 걸립니다. 측정 구간에서는 최소 용량을 올려 콜드 스타트가 측정값에 섞이지 않게 하십시오.
>
> 임베딩 차원과 청크 수는 아직 확정되지 않았습니다. 이 두 값이 pgvector 인덱스 방식과 필요한 DB 용량(ACU)을 결정하므로, 확정 후 산출 근거와 함께 기입합니다.
>
> 구성도가 확정되면 이미지 또는 다이어그램을 첨부합니다.
